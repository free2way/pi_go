# 23 · UI 国际化（中文 / English）

PiGO 的控制台界面支持中英文切换。本文件说明目录结构、如何新增语言/文案、如何运行一致性测试，以及**明确不翻译**的边界。

## 1. 结构

| 位置 | 职责 |
| --- | --- |
| `src/shared/i18n.ts` | 纯函数与词条目录：`zh` / `en` 两套 catalog、`Locale` 类型、`DEFAULT_LOCALE`、`LOCALE_STORAGE_KEY`、`resolveLocale`、**请求语言解析 `localeFromAcceptLanguage` / `resolveRequestLocale`**（§9）、`t`、`intlLocale`、错误码映射 `ERROR_CODE_KEYS` / `localizeError`。不触碰 DOM。 |
| `src/client/i18n.ts` | 浏览器侧状态：`createLocaleStore`（可注入 storage/navigator/apply，便于测试）、`localeStore` 单例、`useT()` hook、`applyLocaleToDocument`（`<html lang>`、`document.title`、meta description）。 |
| `src/shared/decision-brief.ts` | Decision Brief 判定文案的两套文本（`BRIEF_COPY_ZH` / `BRIEF_COPY_EN`）；中文进既有字段，英文进 `*En`（§9）。 |
| `src/worker/runtime-locale.ts` | Worker 运行期 locale：`runLocale`（读 `run.locale`，缺省中文）、`guardText`（渲染 + `meta.locale`/`meta.messageEn`）、guard/stop 文案表（§9）。 |
| `src/worker/prompt-locale.ts` | Agent 提示词的语言指令块 `localeInstruction`，唯一需要回滚的 prompt 改动（§10）。 |
| 各页面 / 组件 | 通过 `useT()` 拿 `t` 与 `locale`，所有可见文案都从 catalog 取；纯展示型 view helper 只返回**键**或接受 `locale` 参数（见 §4）。 |
| `docs/23-i18n.md` | 本文件。 |

关键常量：

- `LOCALE_STORAGE_KEY = "pigo.locale"`（`localStorage`）。
- `LOCALES = ["zh", "en"]`；`LOCALE_LABELS = { zh: "中文", en: "English" }`。
- `DEFAULT_LOCALE = "zh"`。
- `LOCALE_TAGS = { zh: "zh-CN", en: "en-US" }`（用于 `<html lang>` 与 `Intl`）。

语言解析顺序（`resolveLocale(stored, navigatorLanguages)`）：**已保存的选择 > 浏览器语言（首个 `en*` / `zh*`）> 默认中文**。存储不可用（隐私模式等）时静默降级，不影响界面。

## 2. 切换与持久化

- 顶部栏（`src/client/App.tsx` 的 `.topbar-actions`）有一个 `<select class="locale-select">`，选项为 `中文 / English`。
- 切换时调用 `localeStore.setLocale()`：写入 `localStorage` → 更新 `<html lang>` / 标题 / meta description → 通知所有订阅者。组件通过 `useT()`（`useSyncExternalStore`）订阅，因此**无需刷新**即可整体重渲染。
- 默认文案（如新建任务对话框里的演示任务文本）在**首次挂载**时按当时语言取一次，之后不再改写用户已输入的内容。

## 3. 新增一条文案

1. 在 `src/shared/i18n.ts` 里找到对应分区对象（如 `zhRun` / `enRun`、`zhPages` / `enPages`、`zhAgile1` / `zhAgile2`、`zhErrors` …），**两边同时**加同名 key：
   ```ts
   // zhAgile1 / enAgile1 同步新增
   "agile.foo.bar": "示例文案 {count} 条",
   "agile.foo.bar": "{count} example(s)",
   ```
2. 组件里调用 `const { t } = useT();` 后 `t("agile.foo.bar", { count: 3 })`。
3. 运行 `npm run typecheck`：`en` 被声明为 `Record<keyof typeof zh, string>`，**缺 key / 多 key 都会编译报错**，因此两种语言天然对齐。
4. 占位符统一写作 `{name}`；`interpolate` 只替换出现的参数，未知占位符原样保留。

约定：

- 分区对象里的 key 不得重复——`duplicateCatalogKeys(locale)` 会检查并在测试中失败。
- 值不得为空或纯空白。
- 两种语言同一 key 的**占位符集合必须一致**（测试会逐一比对）。
- 动态枚举（run 状态、故事状态、列、gate、错误码……）通过返回 `MessageKey` 的映射函数取键，例如 `runStateKey`、`storyStatusKey`、`boardColumnKey`、`decisionGateKeys`、`ROUND_STATUS_KEYS`。

## 4. 纯 helper 的约定（保持测试有意义）

`src/client/*.ts` 里的 view helper 之前直接返回中文标签。现在遵循：

- **返回键**：`priorityKey` / `estimateKey` / `boardColumnKey` / `storyStatusKey` / `sprintStatusKey` / `releaseStatusKey` / `deployStatusKey` / `roundStatusKey` / `runStateKey` / `humanNoteKindKey` / `decisionGateKeys` / `RELEASE_DEPLOY_ACTION_KEYS` / `decisionBriefHeadingKey` / `decisionRemainingGroupKey`。测试断言“键 + 用 catalog 渲染出的文本”，既不丢原有覆盖点，也不把语言烘进 helper。
- **接受 `locale` 参数（默认中文）**：`agileFormErrorMessage`、`buildTemplateInput`、`buildReleaseInput`、`formatAge` / `formatCost` / `formatVersion` / `databaseLabel` / `workerLabel` / `storageLabel` / `activeRunsSummary` / `failureCategoryLabel` / `failureCategoryRows` / `jobStateRows`、`verificationBadge` / `modelCapabilityHint` / `availabilityLabel`、`mergeOptionState`、`cleanup*`、`decisionBriefHeading` / `continueConfirmMessage` / `acceptConfirmMessage`、`roundStatusLabel`、`formatHistoryTime`、`describeMergeRestore`。默认值让服务端调用方与既有测试保持不变。
- **结构化分组**：`groupRemainingByAc` 返回 `{ kind: "ac" | "unknown" | "unmapped", ac?, items }`，组件负责渲染标签；`groupStoriesByColumn` 不再携带 `label`，只给 `id`。

## 5. 服务端错误码 → 本地化文案

服务端 API **不变**：仍然返回中文 `message` + 稳定的 `code`。客户端侧新增映射（`src/shared/i18n.ts`）：

```ts
localizeError(locale, error, fallback?)
```

- `error.code` 命中 `ERROR_CODE_KEYS` ⇒ 用当前语言的 catalog 文案（忽略服务端中文 `message`）。
- 否则 ⇒ 服务端 `message`；再否则 ⇒ 调用方 `fallback`；最后 ⇒ `error.generic`。

已覆盖的主要码：`ADMIN_REQUIRED`、`BLOCKED_BY_RUN`、`BLOCKED_BY_MANUAL`、`STORY_NOT_READY`、`STORY_NOT_REOPENABLE`、`RELEASE_IN_PROGRESS`、`RELEASE_BLOCKED`、`RELEASE_RELEASED`、`RELEASE_*`、`SANDBOX_UNAVAILABLE`、`WORKER_SHUTTING_DOWN`、`PERSONAL_CREDENTIALS_REQUIRED`、`MODEL_*`、`MERGE_*`、`OPEN_FINDINGS`、`RUN_*`、`WORKSPACE_DIRTY`、`CONFIRM_REQUIRED`、`INVALID_STATE_TRANSITION` 等（完整清单见 `ERROR_CODE_KEYS`）。

仍按码处理的表单/工作区/账户错误（`agileFormErrorMessage`、`describeError`、`describeAccountError`）同样改为读 catalog；其“看着给定的服务端 `message`”优先级保留，因为那些消息通常带有具体的名称/路径。

## 6. 明确不翻译（当前边界）

§9/§10 之后，**服务端/Worker 代码生成的运行时文本**的边界如下。

### 已本地化（本次新增，见 §9 / §10）

- **Decision Brief 的判定文本**：`gate.detail`（含四个 gate）、`recommendation.note`、`stopReason.message`、`diff.detail`。既有字段仍是中文（逐字节不变），英文放在新增的 `detailEn` / `noteEn` / `messageEn` / `diff.detailEn` 字段里。
- **Worker 的 guard/stop 事件文本**（即 Decision Brief 的 stop reason 词表 `STOP_REASON_CODES`）：`run.needs_human`、`review.not_converging`、`review.severe_finding_repeated`、`run.completion_blocked`、`checks.blocked_retry_review`、`run.deadline_exceeded`、`run.budget_exhausted`、`review.provider_error`、`review.invalid_protocol`、`review.snapshot_failed`、`review.snapshot_diverged`、`review.changes_requested`，以及终结路径（取消 / 存储错误 / provider 报错 / 恢复失败 / 沙箱不可用）的 message + summary。这些事件同时记录 `meta.locale`（写入时用的语言）与 `meta.messageEn`（英文变体）。
- **Agent 提示词语言**：developer / repair / integrator / sub-agent / reviewer / planner 的 prompt 里新增一个统一的语言指令块（§10），要求 Agent 用运行语言撰写摘要、findings 的 `title`/`evidence`/`requiredChange`、计划说明与对话内容。

### 仍为中文（原文，不在本次范围）

- **历史行**：本次改动前写入的 `run_events.message` / `meta`、以及所有 `run_findings` 的 title/evidence/requiredChange（模型当时输出的语言）永不改写——审计保真。
- **本次改动后才产生的模型输出**：当运行语言为 `en` 时新 prompt 会要求英文，但模型仍可能输出中文；模型输出不由代码保证。
- **其它运行事件**：`run.created`、`round.started`、`plan.*`、`review.started`、`review.approved`、`agent.activity`、`checks.*`（上面列出的 stop 事件除外）、`diff.artifact_persisted`、`review.nonblocking_deferred`（`deferredMessage`）等进度/活动文本。
- **聊天与检查输出**：`chat.message` 的正文（模型输出）、检查命令的 stdout/stderr、artifact 内容。
- **服务端错误 `message`**：仅当 `code` 不在映射表里时才会显示（原文）。
- **服务端返回的验证标签**：`verificationLabel`（如「已验证」「未校验（操作者断言）」）优先于本地 catalog，因为它是服务端对探测结果的描述。
- **演示运行的脚本化事件**（`src/server/demo-runner.ts` 的固定剧情文本）。
- **日志、部署脚本、`index.html` 的静态默认值**（`lang="zh-CN"` 与中文标题，作为默认语言的初始值，运行时会被 `applyLocaleToDocument` 覆盖）。

## 8. 新增一门语言

1. `Locale` 增加成员（如 `"ja"`），`LOCALES` / `LOCALE_LABELS` / `LOCALE_TAGS` 同步。
2. 复制 `zh` 分区对象为 `ja*`，逐个翻译；在 `en`/`ja` 的 `Record<keyof typeof zh…, string>` 注解下编译期会强制补齐。
3. `resolveLocale` 的浏览器匹配分支加一条（如 `ja` 前缀）。
4. 把该语言的 `*` 分区对象加入 `CATALOGS` 组装；`duplicateCatalogKeys` 的分区数组也要加入，测试即覆盖。
5. 运行 `npm test` 与 `npm run typecheck`。

## 9. 服务端 / Worker 运行时文案（Decision Brief 判定文本 + guard 事件）

### 9.1 locale 的来源与记录

- **`resolveRequestLocale(acceptLanguage, queryLocale)`**（`src/shared/i18n.ts`，纯函数）：请求的 `Accept-Language` 优先 → `?locale=` 查询参数兜底 → `DEFAULT_LOCALE`（中文）。`localeFromAcceptLanguage` 只认 `zh*` / `en*`，`*`、空串、无 zh/en 的 header 一律返回 `undefined` 而不猜测。因此**不表达任何偏好的请求（含所有既有调用方）读到中文**，行为逐字节不变。
- **`Run.locale?: Locale`**（`src/shared/types.ts`）：创建运行时由 `POST /api/runs` / `POST /api/stories/:id/runs` 的路由写入（demo 与 real 两条路径都写），随 run 文档持久化。既有运行没有该字段 ⇒ 读取为 `zh`（`runLocale()`，`src/worker/runtime-locale.ts`）。客户端在 `api.createRun(..., { locale })` 与 `api.decisionBrief(id, locale)` 上发 `Accept-Language`，让"应用内语言选择"覆盖浏览器默认。
- **记录**：本地化过的 guard/stop 事件在 `meta` 里写 `locale`（写入时用的语言）与 `messageEn`（英文变体）；Decision Brief 的 `locale` 字段记录**请求**的语言，`stopReason.locale` 回显事件的 `meta.locale`。读者因此总能判断一段文本是什么语言写的。

### 9.2 加法式 API 形状（向后兼容）

| 位置 | 既有字段（不变，中文） | 新增字段 |
| --- | --- | --- |
| `DecisionBrief` | — | `locale: "zh" \| "en"`（请求的语言） |
| `gate[]` | `detail` | `detailEn?` |
| `recommendation` | `note` | `noteEn?` |
| `stopReason` | `message`、`meta` | `messageEn?`、`locale?` |
| `diff` | `detail` | `detailEn?` |

- 服务端**总是同时生成两种语言**（`src/shared/decision-brief.ts` 的 `BRIEF_COPY` 表驱动四个 gate / 推荐 / diff 文案），所以客户端切换语言时**不需要重新请求**：`decisionGateDetail` / `decisionRecommendationNote` / `decisionStopMessage`（`src/client/decision-brief-view.ts`）按当前 UI 语言取字段，缺 `*En`（旧 payload 或手工 fixture）时安全回退到中文字段。
- 中文路径逐字节不变：所有生成函数默认 `zh`，既有测试与服务端调用方无需改动即通过。

### 9.3 guard / stop 事件

Worker 用 `guardText(text, locale)`（`src/worker/runtime-locale.ts`）渲染消息并拿到 `meta`，`planRecovery` / `convergenceStop` 这类纯函数走 `localizedPair` / `messageEn`。覆盖的事件见 §6「已本地化」。**已写入的 `run_events` 行永不改写**：只有新产生的文本按 locale 渲染。

## 10. Agent 提示词的语言指令块

`src/worker/prompt-locale.ts` 里的 **`localeInstruction(locale)`** 是本次唯一的 prompt 语义改动，也是唯一需要回滚的地方（删掉各 prompt 数组里的这一项与该文件即可）：

- 前缀固定为 `LOCALE INSTRUCTION`，所以能在 prompt 日志里一眼定位/审计。
- `en` ⇒ 要求把 summary、每个 finding 的 `title`/`evidence`/`requiredChange`、计划说明与对话内容写成英文（代码/路径/命令/标识符保持原样）。
- `zh`（默认）⇒ 要求一律中文。
- 追加位置：planner、developer（单 Agent）、repair、integrator、sub-agent、reviewer 六处 prompt 的**最后一段**；JSON 契约、模型选择、工具预算等其它 prompt 语义不变。
- 局限：这是对模型的**指令**而非保证——运行语言为 `en` 时模型仍可能输出中文（§6）。
