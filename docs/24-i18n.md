# 23 · UI 国际化（中文 / English）

PiGO 的控制台界面支持中英文切换。本文件说明目录结构、如何新增语言/文案、如何运行一致性测试，以及**明确不翻译**的边界。

## 1. 结构

| 位置 | 职责 |
| --- | --- |
| `src/shared/i18n.ts` | 纯函数与词条目录：`zh` / `en` 两套 catalog、`Locale` 类型、`DEFAULT_LOCALE`、`LOCALE_STORAGE_KEY`、`resolveLocale`、`t`、`intlLocale`、错误码映射 `ERROR_CODE_KEYS` / `localizeError`。不触碰 DOM。 |
| `src/client/i18n.ts` | 浏览器侧状态：`createLocaleStore`（可注入 storage/navigator/apply，便于测试）、`localeStore` 单例、`useT()` hook、`applyLocaleToDocument`（`<html lang>`、`document.title`、meta description）。 |
| 各页面 / 组件 | 通过 `useT()` 拿 `t` 与 `locale`，所有可见文案都从 catalog 取；纯展示型 view helper 只返回**键**或接受 `locale` 参数（见 §4）。 |
| `docs/23-i18n.md` | 本文件。 |

关键常量：

- `LOCALE_STORAGE_KEY = "pigo.locale"`（`localStorage`）。
- `LOCALES = ["zh", "en"]`；`LOCALE_LABELS = { zh: "中文", en: "English" }`。
- `DEFAULT_LOCALE = "zh"`。
- `LOCALE_TAGS = { zh: "zh-CN", en: "en-US" }`（用于 `<html lang>` 与 `Intl`）。

语言解析顺序（`resolveLocale(stored, navigatorLanguages)`）：**已保存的选择 > 浏览器语言（首个 `en*` / `zh*`）> 默认中文**。存储不可用（隐私模式等）时静默降级，不影响界面。

## 2. 切换与持久化

- 顶部栏（`src/client/App.tsx` 的 `.topbar-actions`）有一个 `<select class="locale-select">`，选项为 `中文 / English`。
- 切换时调用 `localeStore.setLocale()`：写入 `localStorage` → 更新 `<html lang>` / 标题 / meta description → 通知所有订阅者。组件通过 `useT()`（`useSyncExternalStore`）订阅，因此**无需刷新**即可整体重渲染。
- 默认文案（如新建任务对话框里的演示任务文本）在**首次挂载**时按当时语言取一次，之后不再改写用户已输入的内容。

## 3. 新增一条文案

1. 在 `src/shared/i18n.ts` 里找到对应分区对象（如 `zhRun` / `enRun`、`zhPages` / `enPages`、`zhAgile1` / `zhAgile2`、`zhErrors` …），**两边同时**加同名 key：
   ```ts
   // zhAgile1 / enAgile1 同步新增
   "agile.foo.bar": "示例文案 {count} 条",
   "agile.foo.bar": "{count} example(s)",
   ```
2. 组件里调用 `const { t } = useT();` 后 `t("agile.foo.bar", { count: 3 })`。
3. 运行 `npm run typecheck`：`en` 被声明为 `Record<keyof typeof zh, string>`，**缺 key / 多 key 都会编译报错**，因此两种语言天然对齐。
4. 占位符统一写作 `{name}`；`interpolate` 只替换出现的参数，未知占位符原样保留。

约定：

- 分区对象里的 key 不得重复——`duplicateCatalogKeys(locale)` 会检查并在测试中失败。
- 值不得为空或纯空白。
- 两种语言同一 key 的**占位符集合必须一致**（测试会逐一比对）。
- 动态枚举（run 状态、故事状态、列、gate、错误码……）通过返回 `MessageKey` 的映射函数取键，例如 `runStateKey`、`storyStatusKey`、`boardColumnKey`、`decisionGateKeys`、`ROUND_STATUS_KEYS`。

## 4. 纯 helper 的约定（保持测试有意义）

`src/client/*.ts` 里的 view helper 之前直接返回中文标签。现在遵循：

- **返回键**：`priorityKey` / `estimateKey` / `boardColumnKey` / `storyStatusKey` / `sprintStatusKey` / `releaseStatusKey` / `deployStatusKey` / `roundStatusKey` / `runStateKey` / `humanNoteKindKey` / `decisionGateKeys` / `RELEASE_DEPLOY_ACTION_KEYS` / `decisionBriefHeadingKey` / `decisionRemainingGroupKey`。测试断言“键 + 用 catalog 渲染出的文本”，既不丢原有覆盖点，也不把语言烘进 helper。
- **接受 `locale` 参数（默认中文）**：`agileFormErrorMessage`、`buildTemplateInput`、`buildReleaseInput`、`formatAge` / `formatCost` / `formatVersion` / `databaseLabel` / `workerLabel` / `storageLabel` / `activeRunsSummary` / `failureCategoryLabel` / `failureCategoryRows` / `jobStateRows`、`verificationBadge` / `modelCapabilityHint` / `availabilityLabel`、`mergeOptionState`、`cleanup*`、`decisionBriefHeading` / `continueConfirmMessage` / `acceptConfirmMessage`、`roundStatusLabel`、`formatHistoryTime`、`describeMergeRestore`。默认值让服务端调用方与既有测试保持不变。
- **结构化分组**：`groupRemainingByAc` 返回 `{ kind: "ac" | "unknown" | "unmapped", ac?, items }`，组件负责渲染标签；`groupStoriesByColumn` 不再携带 `label`，只给 `id`。

## 5. 服务端错误码 → 本地化文案

服务端 API **不变**：仍然返回中文 `message` + 稳定的 `code`。客户端侧新增映射（`src/shared/i18n.ts`）：

```ts
localizeError(locale, error, fallback?)
```

- `error.code` 命中 `ERROR_CODE_KEYS` ⇒ 用当前语言的 catalog 文案（忽略服务端中文 `message`）。
- 否则 ⇒ 服务端 `message`；再否则 ⇒ 调用方 `fallback`；最后 ⇒ `error.generic`。

已覆盖的主要码：`ADMIN_REQUIRED`、`BLOCKED_BY_RUN`、`BLOCKED_BY_MANUAL`、`STORY_NOT_READY`、`STORY_NOT_REOPENABLE`、`RELEASE_IN_PROGRESS`、`RELEASE_BLOCKED`、`RELEASE_RELEASED`、`RELEASE_*`、`SANDBOX_UNAVAILABLE`、`WORKER_SHUTTING_DOWN`、`PERSONAL_CREDENTIALS_REQUIRED`、`MODEL_*`、`MERGE_*`、`OPEN_FINDINGS`、`RUN_*`、`WORKSPACE_DIRTY`、`CONFIRM_REQUIRED`、`INVALID_STATE_TRANSITION` 等（完整清单见 `ERROR_CODE_KEYS`）。

仍按码处理的表单/工作区/账户错误（`agileFormErrorMessage`、`describeError`、`describeAccountError`）同样改为读 catalog；其“看着给定的服务端 `message`”优先级保留，因为那些消息通常带有具体的名称/路径。

## 6. 明确不翻译（当前边界）

以下内容**仍是原文（中文）**，不在本次范围内：

- **服务端/模型生成的运行时文本**：运行事件 `RunEvent.message`、审核总结、Agent 对话（`chat.message` 的正文与 prompt）、检查输出、artifact 内容。
- **Decision Brief 的判定文本**：`gate.detail`、`recommendation.note`、`stopReason.message`（由 `src/shared/decision-brief.ts` 在服务端生成，随 API 返回）。卡片自身的骨架文案（标题、四个 gate 名称、按钮、分组名、`已返修 N 次未解决` / `疑似误报`）已本地化。
- **服务端错误 `message`**：仅当 `code` 不在映射表里时才会显示（原文）。
- **服务端返回的验证标签**：`verificationLabel`（如「已验证」「未校验（操作者断言）」）优先于本地 catalog，因为它是服务端对探测结果的描述。
- 日志、部署脚本、`index.html` 的静态默认值（`lang="zh-CN"` 与中文标题，作为默认语言的初始值，运行时会被 `applyLocaleToDocument` 覆盖）。

## 7. 测试

```bash
npm test            # 全量（含 i18n）
npm run typecheck   # catalog 键集对齐（编译期）
npm run lint
npm run build
```

新增测试：

- `src/shared/i18n.test.ts`
  - 目录一致性：两语言 key 集相同、key 数量下限、**无重复 key**（`duplicateCatalogKeys`）、**无空值**、**占位符集合一致**。
  - `interpolate`：命名替换、未知占位符保留、缺参数不抛。
  - `t`：按语言渲染 + 插值；未知 key 返回 key 本身（永不抛错）；未知语言回退到默认 catalog。
  - `resolveLocale`：存储优先、浏览器次之、默认兜底；非法存储值忽略；`isLocale`；存储键稳定。
  - 错误码映射：主要码齐全、已知码忽略中文 `message`、未知码回退服务端消息、每个映射码在两种语言都有文案。
- `src/client/i18n.test.ts`
  - 持久化：读取有效/非法值、storage 抛错时降级、按 `LOCALE_STORAGE_KEY` 写入。
  - 切换：`createLocaleStore` 初始解析顺序、`setLocale` 持久化 + `apply` + 通知订阅者、重复选择幂等、取消订阅后不再通知、显式 `initial` 覆盖存储。
  - 文档集成：`applyLocaleToDocument` 设置 `html lang` / title / meta description；无 document 时空操作。

## 8. 新增一门语言

1. `Locale` 增加成员（如 `"ja"`），`LOCALES` / `LOCALE_LABELS` / `LOCALE_TAGS` 同步。
2. 复制 `zh` 分区对象为 `ja*`，逐个翻译；在 `en`/`ja` 的 `Record<keyof typeof zh…, string>` 注解下编译期会强制补齐。
3. `resolveLocale` 的浏览器匹配分支加一条（如 `ja` 前缀）。
4. 把该语言的 `*` 分区对象加入 `CATALOGS` 组装；`duplicateCatalogKeys` 的分区数组也要加入，测试即覆盖。
5. 运行 `npm test` 与 `npm run typecheck`。
